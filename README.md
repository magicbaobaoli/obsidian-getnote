# 得到大脑 Get笔记 · Obsidian 插件

把「得到大脑（Get笔记）」搬进 Obsidian。**本地优先**：笔记就是你自己库里的 Markdown 文件，
浏览、搜索、编辑、删除全部离线可用；云端同步、录音卡导入是需要时再打开的增强项。

> 这是 [dsh-getnote](https://github.com/magicbaobaoli/dsh-getnote)（DeepSeek Harness 版）的 Obsidian 移植。
> 功能对齐，但宿主不同：那边挂在 DSH 的 webServer 上，这边是一个标准 Obsidian 插件。

---

## 功能

### 本地笔记库

- **三栏面板**：目录树 / 笔记列表 / 正文，支持按目录、标签、关键词过滤，两种排序。
- **Markdown 原样渲染**：标题、列表、表格、引用、代码块、任务清单、内嵌图片与音频。
- **编辑与保存**：面板内直接改正文并保存；每次保存前自动在 `.history/` 留一份快照，可回滚。
- **新建 / 删除**：新建可指定目录与日期前缀；删除进 `.trash/`，可还原、可彻底清除。
- **搜索**：全文搜索，支持 `tag:` 与 `path:` 限定语法，结果带上下文片段。
- **反链与大纲**：`[[wikilink]]` 反链、标题大纲、冲突文件（`.conflicts/`）识别与解决。
- **标签**：重命名、删除、批量改写，标签面板带计数。
- **热力图**：按天统计的写作/导入活动。
- **三栏可拖**：左栏、中栏之间的分隔条能拖动调宽，也能用方向键微调；宽度记在本地，下次打开还是你调的样。
- **右键菜单**：笔记卡片上右键出 Obsidian 原生菜单——打开、复制引用、单篇推到云端、从云端拉下来、删除。
- **命令面板与状态栏**：`Ctrl+P` 里有搜索笔记、新建笔记、打开今天的笔记、立即同步、扫描录音卡、**选区速记**、快速切换、在得到大脑里打开当前笔记等命令，不必先打开面板；状态栏常驻一行小字显示本地服务端口与库的大小，点一下打开面板。
- **选区速记**：在任意笔记里选中一段文字，跑「得到大脑：选区速记」，这段文字就落成一篇新笔记——第一行当标题，正文是引用块，末尾注明摘自哪里。摘录和自己的话必须一眼分得开，所以用引用块而不是直接粘。
- **深链**：`obsidian://getnote?action=search&q=关键词`、`action=new|today|sync` 可以直接从任何地方唤起面板并执行对应动作，`action=open&path=...` 则直接跳到某一篇（库内相对路径与面板口径两种写法都收）。只做导航与同步，不做写操作——一个能被任意网页触发的 URL 不该有删笔记的能力。
- **同步摘要写进日记**：面板（或命令面板）跑完一轮同步后，把「新增 N 篇、跳过 M 篇、K 处冲突」追加到当天的日记里（读 Obsidian 日记核心插件的目录与日期格式设置；插件没启用就不写）。

### 云端同步（可选）

两条通道，任选其一或自动回退：

| 通道 | 凭证 | 说明 |
| --- | --- | --- |
| **Open API** | API Key + Client ID + Grant ID | 直接调 `openapi.biji.com`，最省事 |
| **MCP / OAuth** | 浏览器授权（PKCE） | 走 RFC 7591 动态注册，不需要手动申请 Key |

- 单向拉取（云端 → 本地）、逐条推送与「把本地改动推上去」（本地 → 云端）。
  批量推送按内容指纹跳过没改过的笔记，不白吃配额，也不会把云端修改时间刷成现在。
- 图片可选一起下载到 `asset/`。
- 定时自动同步：可设间隔（5–720 分钟）、增量模式、仅面板可见时同步。
- 首次调用失败会自动从 Open API 回退到 MCP 通道，并在状态里标注失败原因。
- 逐字稿与录音联动：点逐字稿里的 `[mm:ss]` 时间戳，播放器跳到那句开始播；播放时正在念的那段会高亮。

### 录音卡导入（可选，需 Python）

- **蓝牙直连**：扫描、读取信息、按文件列表导入、按需删除卡内文件。
- **Wi-Fi 传输**：让卡开热点或连你的路由器，走 HTTP 拉取，比蓝牙快得多。
- 导入后自动按日期与标题命名，写进库并生成 Markdown 笔记；可配置「导入后删卡内文件」。

> 录音卡直连需要 **Python 3.10+** 和 `bleak` 包（`pip install bleak`）。
> 插件会在设置页检测环境，缺什么会直接告诉你。蓝牙是**只读**的：
> 默认永不发送「清理已传输文件」指令，只在你显式勾选「导入后删除」时按文件名删除。

### 其它

- **归档包**：整库导出为 zip、从 zip 导入（可选合并/覆盖模式）。导出可选范围——整库 /
  只要文字 / 只要附件；附件常常比笔记大两个数量级，只想备份文字的人不该每次等几百兆。
- **Bases 视图**：一条命令在笔记目录里生成 `得到大脑.base`——全部 / 按标签 / 按日期三个视图，
  想在 Bases 里自己写公式、自己排表都行，不必回到面板。已经存在就不覆盖（你可能已经调过了），
  但会顺手把它打开——只写文件什么都不发生，会让人以为命令没生效。
- **画布**：一条命令把当前笔记放进 `得到大脑画布.canvas`，没有就新建一张。只补节点，
  不重排你摆好的布局；同一篇加两次也只留一个节点。写完直接打开画布，接着就能拖。
- **模板**：保存常用正文模板，新建时一键套用（最多 12 个）。
- **多语言**：中文 / English / Nederlands。
- **主题**：跟随 Obsidian 主题，深浅色自动适配。
- **贴着宿主走**：界面字体、正文字体、等宽字体与字号都读 Obsidian 的 CSS 变量
  （`--font-interface` / `--font-text` / `--font-monospace` / `--font-text-size`），
  你在外观设置里换字体、调字号、改缩放，面板跟着变；宿主发 `css-change` 时立刻重算。
- **不可逆动作问宿主**：删除、清空、覆盖这类动作弹的是 Obsidian 原生 `Modal`，
  默认焦点在「取消」。移动端 WebView 里 `window.confirm` 可能根本不弹，等于没有二次确认。
- **在 Obsidian 里打开**：面板编辑器只服务「扫一眼、改两笔」，没有补全、没有 Vim、
  没有插件命令。笔记头上一个按钮把它交给宿主编辑器，要动结构就回那边去。
- **反链走宿主的链接索引**：宿主一直在增量维护整库链接图（`metadataCache`），
  面板直接问它，不再为一次反链把全库正文重读一遍。问不到才退回自己扫。
- **出错就说清楚，不留一片黑**：面板是整棵 React 树，打开时任何一步抛错（注入样式、
  建根节点、首帧渲染）在屏幕上留下的都是一模一样的黑。现在这些异常会被接住，直接画成
  一段可读的报错——标题、原因、前八行堆栈，内联样式写在块上，不依赖那份可能正是没注入
  成功的 CSS；同时往插件目录写一份 `panel-error.txt`，不用去翻控制台。另外还有一道看门狗：
  渲染调用不抛错不等于真画出来了，两秒后回查根节点，没出现就说「首帧没有渲染完成」，
  出现了但高度是 0 就说「布局没有撑开」——这两种在屏幕上一样黑，原因却完全不同。
  骨架屏上也一直压着一行字：占位色块用的是宿主主题里的 hover 色，碰上把它调得和背景
  几乎一样的主题，三栏骨架就是一片黑，与「渲染挂了」分不出来——那行「正在读取笔记库…」
  是黑屏里唯一的确定信息。等过六秒还没取到就改成「本地服务好像没连上」并给一颗「重试」，
  无限转圈和一片黑对用户是同一件事，都得给个能按的东西。
  还有一种黑更彻底：工作区里留着一个从没跑过 `onOpen` 的空壳叶子，
  `revealLeaf` 它一百次也还是空壳，连兜底报错都轮不到。现在打开前先看容器里有没有面板
  留下的节点，是空壳就换一个新的。
  还有一种黑是宿主自己造成的：视图被挂上了、构造函数也跑了、容器就在那儿，可宿主一次都没
  调 `onOpen`——没人画，屏幕自然一片黑，连报错都不会有。现在挂上去一秒半之后回看一眼：
  这几行轨迹里没有「视图 onOpen 被调用」，就自己补调一次，让面板照样画出来；宿主后来真调了，
  那边也只生效一次，不会画两遍。
  最要紧的一处是：插件以前把宿主那个 `containerEl` 改写成了自己的挂载点。那是宿主记「这个
  视图挂在哪儿」的字段，被换掉之后面板照常渲染、轨迹里每一步都对，画出来的树却不在屏幕上——
  用户看到的永远是整片黑。现在挂载点单独记在 `panelEl` 上，宿主的 `containerEl` 一个字节都不碰；
  看门狗还会在容器始终没挂进文档时明说「画在屏幕外了」。
  真要报问题的时候，这些轨迹以前只在插件目录的 `boot.txt` 里——得先知道有这回事、再找到
  那个文件。现在设置页底下有一块「面板打不开的时候」：点「看最近的轨迹」把这次启动走过的
  每一步摊在页面上，点「复制」直接进剪贴板，截图或粘贴就能说清卡在哪一步。
- **窄窗口能收能放**：Obsidian 的侧栏可以只有两三百像素，popout 窗口也能随便拉。
  面板用容器查询盯自己的实际宽度（不是视口宽度——窗口很宽但侧栏很窄是常态）：
  窄了左栏变成抽屉、有笔记时中栏让位，笔记头上有「返回列表」。
- **编辑态跟宿主编辑器一个口径**：Ctrl/Cmd+S 保存、Esc 退出编辑，不用先想起来
  「这是插件里的编辑器」。
- **状态栏跟着面板走**：库里有几篇、当前开着哪一篇，直接写在 Obsidian 的状态栏上，
  点一下打开面板。只有「得到大脑」四个字的话，用户既不知道库多大也不知道在看什么。
- **快速切换器（Ctrl/Cmd+O）**：命令面板里有一条「快速切换：打开得到大脑笔记」，
  列的是库里的全部笔记（带目录前缀，同名笔记分得开），选中就直接在面板里打开。
  找笔记的第一反应是 Ctrl+O，不是翻 ribbon——顺着这个习惯来，库里的笔记才跟宿主
  自己的笔记一样好找。
- **右键菜单里也有我们**：在文件树里右键笔记目录里的 Markdown，多两条——「在得到大脑里打开」，
  和「在得到大脑里搜索这一篇的名字」（名字就在手上，想找同一摊的其它篇时不用再抄一遍）；
  在编辑器里右键，多一条「把选中的文字存进得到大脑」（没选中就是当前这一行）；选着字的时候
  还多一条「用选中的文字搜索得到大脑」——读到一句话想找库里还有哪篇提过它，不用先复制再
  粘进搜索框。只往宿主自己的菜单里加条目，不接管菜单——别的插件的条目照旧。笔记目录外的
  文件不会冒出来。
- **别处改了，面板当场跟着变**：在 Obsidian 编辑器里改了当前这篇、或者把它删了改了名，
  面板立刻跟着换（以前只有重新点一次卡片才重读，开着的那一篇等于停在过去）。
  面板自己保存的那一下不算「别处改了」，不重复读；有没保存的草稿时不覆盖你正在改的内容。
- **列表里能把笔记拖出去**：在列表里按住一篇拖到宿主的编辑器里，落下去就是一条链接
  （格式跟「复制引用」同一套，取决于你自己的链接设置）。想把它引到正在写的那篇里时，
  拖过去比「复制引用 → 切窗口 → 粘贴」顺手。
- **列表里右键就能拿去改**：右键菜单里也有「在 Obsidian 里打开」——扫到一篇想拿宿主的
  补全、Vim、别的插件命令去改时，不必先点开再回头找按钮。面板三种路径口径（库内相对、
  相对笔记目录、绝对）都在交给宿主之前统一换算，右键那条不会因为路径写法不同而找不到文件。
- **复制引用按你的链接习惯来**：点「复制引用」拿到的是 `[[随手记/甲|甲]]` 还是
  `[甲](随手记/甲.md)`，取决于你自己的「使用 Wiki 链接」「新链接格式」设置——这两项
  交给 Obsidian 生成，不是插件自己猜的。粘进另一篇笔记就能用。
- **「今天」用宿主自己的日记模板**：「设置 → 核心插件 → 日记 → 模板文件」指向的那篇
  笔记（标题骨架、几个提问、常用标签），新建今天的日记时会整个填进去——和在宿主里
  新建看到的是同一份。以前我们建一篇空的，同一个库里于是有两种「今天的日记」。
  模板路径宿主记的是库内相对路径，读不到（文件被删、路径写错、插件关着）就当没有。
- **双链带小节也能跳准**：`[[笔记#小节]]`、`[[#本页的小节]]` 在 Obsidian 里会直接滚到
  那一节。以前我们把整串 `笔记#小节` 当路径递过去，宿主找不到这一篇，于是不管点多准都
  只会得到「库里找不到」。现在先切开、把前面那段交给宿主解析，打开之后再按标题文字滚
  过去；同一篇被链到不同小节会显示成「笔记 › 小节」，否则两行链接看起来一模一样，
  点进去落在哪儿全靠猜。那一节被改名或删掉时明说「这一篇里没有这一节」，不是静默不动。
- **这篇引用了谁，也看得见**：笔记底下除了「引用了这篇的笔记」，还会列出这一篇自己
  写了哪些 `[[双链]]`。两个方向合起来才是脑子里那张网——只看反链的话，一篇笔记的
  上下文永远只有一半。出链优先问宿主的索引（它认得别名、竖线前那一段、以及指向库外
  文件的情况），问不到就用读笔记时顺带算好的那份；同一篇写两遍会合掉，点一下就能过去。
- **改名还是宿主那一套**：笔记头、列表右键都能重命名，弹的是 Obsidian 自己的改名
  对话框。这件事不能自己做——宿主改名时会顺手把全库的 `[[双链]]` 和 Markdown 链接
  一起改掉；我们绕过它直接改文件名，别的笔记里的引用就成了死链，往往几个月后才在
  某篇笔记里发现一串点不开的链接。有没保存的改动时先拦住，免得改完重读把那几句
  一起冲掉。
- **图点一下先自己放大**：面板里的图片（正文里的 `![[图]]` 和附件区的图）点一下就地
  铺满一屏看原图，Esc 或点空白处收起——面板里的缩略图只有 200px 高，一张扫描件想看清
  上面的字，以前得把焦点交给 Obsidian、看完再切回来。放大的是同一张图，走的是同一个地址，
  不额外下载一份。没有宿主也能放大；连放大去处都没有时才退回「交给宿主打开」，两样都没有
  就不给光标、不挂点击——挂一个点了什么都不会发生的处理器，比不能点更让人困惑。
  一篇里有好几张图时，遮罩底下摆着「上一张 / 下一张」和「第几张 / 共几张」，左右方向键
  也能走（走到头绕回另一头）；只有一张图就不摆那两颗按钮——一颗按了永远停在原地的
  按钮比没有更糟。
- **图片和录音走宿主的资源协议**：面板里 `<img>` / `<audio>` 的地址问
  `adapter.getResourcePath()`，是宿主自己协议下的地址——浏览器直接加载，吃宿主的缓存，
  录音拖进度条靠的 Range 也归宿主管。以前每张图都要绕一圈本机 HTTP，端口和令牌一换就得重算。
  宿主没给这个方法（旧版本、文件还没进索引）才退回本地服务地址。
- **页面预览也是宿主的**：鼠标停在面板正文里的 `[[双链]]` 上，弹出的预览卡片与在笔记里
  悬停时一模一样——插件只把事件转给宿主，并登记了自己的预览来源。
- **列表里停一下也能预览**：中栏那列卡片以前只能点开才知道是不是要找的那篇；现在鼠标停上去
  就请宿主弹这一篇的预览，跟宿主的文件列表一个手感。用的是 `mouseenter` 而不是 `mouseover`，
  卡片里还有勾选框和命中行，`mouseover` 在它们之间挪一下就重发一次，预览会一卡一顿的。
  宿主没登记预览来源时一条都不触发，宿主那边炸了也只是不弹，不会把面板带崩。
- **剩下的不想一屏一屏点下去**：库大起来之后，中栏一次只渲染一屏，滚到底或点「显示更多」
  再放一屏——想从头翻到尾就得按十几次，每按一次还要把鼠标挪回列表底下。现在「显示更多」
  旁边并排一颗「全部显示」，点一下把剩下的都摊出来，摊完这两颗自己收起来。它摊的是当前
  这次筛选的结果，不是整个库：换个查询窗口就跟着降回一屏，不会把没筛掉的东西也画出来。
- **划一段就能拿走**：读长笔记时想把某一段摘出来单独成篇，以前只能先新建一篇、
  再切回来复制、再粘过去，中间还得记住是哪一段。现在在正文里划选，松手就地弹出小条：
  「复制」把那一段搬进剪贴板，「存成新笔记」直接新建一篇，标题取选中内容的第一行前 30 字，
  正文就是选中的那些字，落在你当前筛的目录里并当场打开。小条只在阅读态摆——编辑态那一块
  是可编辑的 textarea，划选是改字的前奏，在上面弹一颗「存成新笔记」只会挡住正文；
  一滚动就收起（它按视口坐标钉着，正文一滚就飘走了）。
- **挑几篇一起处理，不用先去够勾选框**：批量加标签、挪目录、删掉都要先勾选，可勾选框
  只在悬停或已经选过时才显形——想连着挑几篇得把鼠标在每张卡上停一下，键盘用户更够不着。
  现在按 X 就把当前打开的那一篇选进去（没打开笔记时落在列表第一篇，刚按 j/k 浏览完视线
  就在那儿），再按一次退出；Esc 把整批清掉，和「取消选择」那颗按钮一个效果。速查表里
  也补上了这一行。
- **想留着原稿再改，就复制一份**：写周报时拿上周那篇当骨架、做实验时想保住原稿，
  以前得「复制引用 → 新建 → 粘贴正文 → 自己补标题」四步。现在列表里右键「复制这一篇」
  （笔记头上也有一颗），读一份正文、以「原标题 副本」建一篇新的，落在同一个目录里并当场
  打开——下一步一定是在新篇上动手。副本照抄原篇的名字，不再叠一个今天的日期：用户认的
  是原来那个名字。**原文件一个字都不动**，也不碰你手上那份没保存的草稿——这是「另起一篇」，
  不是「把这篇存成另一篇」。
- **整篇正文一次抄走，不带开头那段属性**：想把这一篇丢给翻译、贴进聊天框、或者喂给模型，
  以前得先打开、再划选、再 Ctrl+C——长笔记一屏一屏划过去很容易漏掉尾巴。现在列表里右键
  「复制正文」就直接把整篇抄进剪贴板，**开头的 frontmatter 不跟过来**（那是给宿主看的，
  不是正文），正文里本来就有的分隔线照留。提示条会说清复制了多少个字，空篇则明说没东西可抄。
- **两个地方都改了同一篇，保存会先问一句**：面板开着这一篇、你顺手在 Obsidian 编辑器里
  也改了几笔（或者另一台设备同步下来一版），以前面板这边一按保存就把对方那份直接盖掉，
  盖完还没有任何提示。现在保存会带上「我读到的是哪一版」，对不上就问一句，两颗按钮写的是
  「存我这一版」和「用别处那一版」——选后者，正文当场换成磁盘上那一份，手上这份丢掉；
  选前者，就真的按你这一版写进去。写之前那一版照旧留在历史里，不是靠这次提示来兜底。
- **选中一段字再粘网址，它就当链接文字**：在宿主编辑器里选中几个字、粘贴一个网址，
  那段话会留在原地变成链接文字；面板的编辑区是个裸 textarea，粘贴会把选好的字整个
  替换成网址，用户还得重新打一遍。现在选中一段字再粘网址，出来的是
  `[那段字](网址)`，光标停在链接文字上，接着打字是改链接文字而不是改网址。
  没选字、剪贴板里不是 http/https 网址、选中的本来就是一条链接、或者选中的字里带
  `]` 与换行（拼出来是坏链接）时一律不插手，交回浏览器默认行为。
- **点双链先问宿主的索引**：面板正文里的 `[[双链]]` 该指向哪一篇，先问
  `metadataCache.getFirstLinkpathDest()`——别名、不带扩展名的路径前缀、同名笔记取离当前
  这篇最近的那篇、大小写按库里实际文件名，这些规则都在宿主那儿。面板自己按「路径 → 文件名
  → 标题」三级退让能应付常见的链接，但同名一多就会指到另一篇上，而「点进去是另一篇」这种
  错很难自己发现。宿主解析不出来（或结果落在笔记目录之外）才退回自己那套。
- **popout 窗口里也长一样**：「在新窗口中打开」出来的面板有自己的一份样式，主题跟着
  那个窗口走，Ctrl+K 聚焦的是它自己的搜索框（不抢主窗口的）——宿主每开一个窗口都是一个
  独立的 document，绑在主窗口上的东西在那里面等于不存在。
- **拖进来就是挪过来**：在 Obsidian 左边的文件树里按住一篇笔记，拖到得到大脑的列表上，
  它就挪进你当前筛的那个目录——不用「复制 → 切目录 → 粘贴」。拖进来的是宿主的路径口径
  （带笔记目录前缀），面板自己换算成库里的相对路径再走同一个批量移动接口；没选目录时
  先说一声，不会瞎猜一个地方放。笔记目录外的东西、非 Markdown 文件一律不理。
- **在文件列表里定位**：列表是平的，想知道这篇在库里挨着什么、旁边还有什么时，
  右键「在文件列表里定位」，宿主的文件列表会把它亮出来。老版本挂在核心插件实例上、
  新版本可能只在叶子视图上，两处都试；都没有就明说「这个版本定位不了」，不静默。
- **「今天」就是宿主那个今天**：命令里的「打开今天的笔记」会先问日记核心插件——
  它把日记配在「日记/YYYY/YYYY-MM-DD」还是别的格式，插件就按那个位置找、按那个名字建，
  不会在同一个库里造出第二个「今天」。日记插件关着、或者日记放在笔记目录之外时，才退回
  自己的「库根 + YYYY-MM-DD」——不替用户把日记搬进笔记目录。
- **新建也落在你习惯的地方**：宿主的「设置 → 文件与链接 → 新建笔记的默认位置」配成
  指定目录或「当前笔记所在目录」时，面板里点「+」建出来的那篇就落在那儿，不会同一个库里
  两套「新建落在哪」。你在面板里自己选了目录就以你选的为准（那是你刚明说的）；宿主的设置
  落在笔记目录之外时不跟——不替你把笔记建到笔记目录外面去。
- **反链能看见「在哪一句」**：底下那块「谁提到了我」不再只给标题和路径，每条底下还带
  引用那一行的上下文——一篇笔记里三处都提到你时，扫一眼就知道为什么被引，不用点进去再
  在正文里搜一遍。双链本身从上下文里削掉（`[[名字]]` 这几个字符不占地方），太长就两头
  留一点、中间省略；同一行里写了两遍只留一条（两行一样的字摆出来只是噪音）。提了几次也
  标出来，提得多的排在前面——一篇里反复提到你的，通常比顺口提一次的更值得先看。这个次数
  接不接宿主都一样算，两边排序口径也一样，不会因为宿主的索引还没跑完就换个顺序。
  接上宿主时这一行要现读引用方的正文（宿主的索引只记得「谁引用、几次」，不存那一行剩下的
  字），所以那条路是异步的：面板会等它答，而不是先摆一份「没有关联笔记」再自己改口。
  这一行现在还能点：点标题是「去那一篇」，点这句话是「去那一句」，打开就落在写着这句话的
  那一段上。反链最常用的场景就是「我记得在哪篇里提过，是哪一段来着」，以前只把人送到篇首，
  还得自己在一整篇里再找一遍。上下文里双链是削掉的、正文里它是个胶囊，整串比对永远对不上，
  所以那句比对是按词顺序找的——只要这几个词依次出现就认它是同一行，中间夹了什么都不管。
- **代码块右上角有个「复制」**：读笔记时想把一段示例命令、报错原文搬去别处，用鼠标
  划选很容易漏掉首尾、还会把旁边的语言标签和缩进一起带上。现在每段围栏右上角都有
  一个「复制」，点一下搬走的就是围栏里那一份原文，缩进和引号一个字不改。只在阅读态
  出现——编辑态看到的本来就是原文，再摆一个复制按钮只是挡住字。卡片摘要和嵌进来的
  正文不给：那里没有「复制走」这个去处，点了没反应的按钮比不能点更让人困惑。
- **待办都在一张单子上**：待办写在正文里，想知道「还剩哪些没做」就得一篇一篇翻。
  宿主自己有「搜索 `- [ ]`」，但那要你先知道这条语法。现在多了一个「待办」页签，点开
  就把全库还没勾掉的方框列出来：哪一条、在哪一篇、第几行。方框就在这一页上，勾一下
  当场划掉、笔记里那一行真的变成 `[x]`；点文字直接打开那一篇去改。围栏代码块里的
  方框不算（那是示例），注释里的也不算（宿主里根本不显示）。勾完只把那一行从单子上
  拿掉、不整页重查——重查要读全库正文，等两秒你会以为没点上又点一次。一条待办埋在
  几十行之后时，点文字只会送到篇首，还得自己往下找一遍；现在每行多一颗「去这一条」，
  点它就打开那一篇并落到写着这条待办的那一行。这张单子经常要整份抄去别处（周报、群里
  同步），顶上那颗「复制这份清单」按屏幕上这个顺序抄成一段 Markdown：一篇一个小标题，
  下面一行一条 `- [ ]`，已勾掉的不抄。几十条待办散在七八篇里时，按篇分了组：一组前面
  写着这是哪一篇、还剩几条，右边一颗「勾掉这一篇的 N 条」把这一篇的一次勾完（仍然一条
  一条写回笔记，中途出错就重新查一遍，不假装勾上了）。某一篇塞了十几条时，清单会被它
  一个人撑满、别的篇全被顶到屏幕外面去；组头前面那颗小箭头点一下就把这一篇的行收起来，
  组头、篇名、还剩几条和那颗「勾掉这一篇的 N 条」都还留着——「这一篇还剩几条」不能跟着
  行一起消失。收起来的地方写一行「这一篇的 N 条收起来了」，再点一下原样摊开。篇数多
  的时候顶上还有一颗「全部收起」，一次把所有篇都收起来、先看清都剩哪几篇，再按一下
  全摊开（全收着时这颗按钮自己改成「全部展开」；只有一篇时不摆，一篇收不收就是那一篇
  自己的箭头）。
- **长表格读到下面，还知道这一列是什么**：一张十几二十行的对照表、词表，滚到下面几屏，表头
  早就滚出去了，只能靠记。现在超过八行的表格单独给一块可滚区域、表头钉在顶上，横向照样能滚；
  短表格不动——一屏就看得完的表再套一层滚动更别扭。
- **写错的那一行，点一下就送到眼前**：断链页原来点一行只打开出问题的那一篇，而那个写错的
  名字往往在整篇的第三十几行——打开之后还得自己往下找一遍。现在每一行旁边多一颗「去这一句」，
  点它就打开那一篇并滚到写着这个名字的那一段（锚的是那一行文字，不是行号，用户刚编辑过也
  照样找得到）。要「打开这一篇」还是「滚到那一行」，两个动作各占各的地方，不会误触。
- **断链一次摊出来**：双链写错一个字的时候一点感觉都没有——点下去没反应，过几个月才发现
  一堆死链，那时已经想不起当初想指哪一篇。现在多了一个「断链」页签，点开就把全库指不到的双链
  一次列出来：哪一篇、第几行、那一行长什么样，点一行直接打开出问题的那篇去改。围栏代码块里的
  不算，`[[笔记#小节]]` 只看小节前面那段，指向图片和 PDF 的当附件放过，别名也认——宁可放过，
  也不要把本来没错的链接报成断的，那样你会去改一堆没问题的东西。
- **搜出来就知道它讲的是哪几篇**：搜索结果的卡片原来只有标题、目录和命中次数——知道这篇
  提到了关键词，却不知道它到底在讲哪几篇，还得点进去翻。现在卡片底下直接列出这一篇引用的
  笔记，点胶囊就跳过去，超过四颗收成「+N」。正文本来就已经读进来了，这一行不额外读盘。
- **双链指空了，就地把它写出来**：点一条指向还不存在的笔记的双链，以前只报一句「库里找不到」——
  可那一刻你其实就想把这一篇写出来，还得退出去新建、自己补标题、自己放对目录。现在那句报错后面
  多一颗「写一篇「某某」」，点一下就用双链里写的那个名字建好，落在当前这一篇所在的目录里（两篇本来
  就该挨着），建完当场打开；名字照抄、不叠今天的日期，否则指不回来。建好之后那条双链当场不再暗。
- **同一个错名字，别再报八遍**：断链页以前是一条一行，同一个名字在七八篇里各写错一次，就是七八条
  一模一样的红字，往下翻两屏都在重复同一件事。现在按名字分组：一处名字一行头，写着它被写错了几处，
  底下才是那一处处的位置。组头右边还有一颗「写一篇」——这个名字本来就该有一篇、只是还没写的时候，
  点一下就在库根把它建出来并当场打开，写完之后这一组自然就不在清单里了。
- **整张断链清单，能一次抄走**：几十处断链光在屏幕上看没用——想一次修完，得知道「哪几个名字指不到、
  各自出现在哪几篇的第几行」。现在断链页顶上多一颗「复制这份清单」：抄出来是一段 Markdown，按名字
  分组，每条带着出处的篇名、行号和那一句原文，贴进任何编辑器都能直接搜。一条断链都没有时不摆这颗
  按钮。
- **名字打错一个字，别再补一篇同名的**：断链绝大多数不是「少了一篇」，是「写错了一个字」。以前每组
  只有一颗「写一篇」，补出来之后库里就有两篇讲同一件事的了，原来那篇还是没人引。现在组头还多一颗
  「改指到已有的那篇」：填上本来想指的那一篇（敲字就从库里已有的名字里挑），回车全库一起改过去。
  只换链接的名字，后面跟的 `#小节` 和 `|显示文字` 都原样留着；代码块里的 `[[...]]` 不动。改之前
  先问一句「全库里这 N 处都改过去？」，改完那一组自己从清单上消失。
- **新建时就说清建到哪儿**：新建落在哪原来只看两件事——面板里有没有选中某个目录，没有就
  跟宿主的默认位置。想建到别处只能建完再拖或再挪一次。现在「+」打开的那张菜单顶上多了一行
  目录框，敲字就把库里已有的目录摆出来（打头的排前面），上下键挑、回车或点一下填进去，Esc 先收
  候选、不把已经填好的清掉。填了就以填的为准，留空仍按原来那套走；挑一条只是填名字，真要建
  还得再点一类模板。
 - **刚建好的目录，别让它当场消失**：以前左栏只认有笔记的目录，刚建好一个准备往里写，它当场
   就不见了，看着像根本没建成（提示里还写着「空目录暂时不显示」）。现在空目录照样摆在树上、
   计数写着 0，点进去是一屏「这里还没有笔记」，右键还能把它删掉；新建笔记时那个目录框里也挑得到
   它——刚建好的目录，正是最想往里写的那一个。
- **批量加标签，也不用背标签名**：库里标签是斜杠套斜杠的，凭记忆打一个「读书/笔记」而库里
  叫「读书/摘抄」，加进去的结果是几篇一起贴上一个新标签、旧的还在，事后还得再去一遍。现在批量条
  那个标签框敲字就把库里已有的标签摆出来（打头的排前面），上下键挑、回车或点一下填进去，Esc 先收
  候选、不把已经填好的清掉。挑一条只填名字，加还是要去还是再点那颗按钮——一步选、一步动手。
- **批量挪目录不用再背目录名**：批量条里的「移动」原来是个空输入框，目录名得凭记忆手打——
  打错一个字不是「没找到」，而是当场新建一个目录，事后才发现多出来一摊空壳。现在敲字就把
  库里已有的目录摆出来（打头的排前面），上下键挑、回车或者点一下填进输入框，Esc 先收候选
  不把已经填好的清掉。挑一条只填名字、不动文件，填好再按「移动」才真的挪——一步选目标、
  一步动手，手滑也不会当场把几篇笔记搬走。
- **目录名打错了，右键就能改**：目录名就是磁盘上的文件夹名，所以以前只能在系统里改名、
  再回来逐篇搬。现在目录行右键多一项「改名」，填个新名字回车，整棵子树连同里面所有笔记
  一起搬过去；新名字撞上已有目录、或者填的是插件自己保留的那些名字，当场说一声就不动。
  正开着的那一篇要是在这棵子树里，笔记头那行路径跟着换成新位置——否则再按保存会写回旧地方。
- **想往哪个目录里写，就在那个目录上点右键**：以前只有顶上那颗「+」，建完还得在菜单里把目录名
  打一遍（或者建完再挪一次）。现在目录行右键多一项「在这里新建笔记」，点一下就直接建在这个目录里、
  当场打开，标题仍是「新建笔记」那个默认名，接着写就行。
- **整个左栏嫌乱，一颗按钮全收起来**：目录和标签各攒到二三十支之后，一支一支点小箭头
  是几十次点击，而「只想看看顶层有哪几摊」恰恰是最常见的一眼需求。现在目录区和标签区
  的标题行各多一颗小三角：按一下把这一区里所有能收的行一次收起来（按钮自己转成「全部展开」），
  再按一下全摊开；两区互不牵连，全是叶子的那一区不摆这颗按钮。
- **标签多的时候也能收起来**：标签按斜杠摊成层级之后，同一支底下会攒出七八行。
  现在有子标签的那一行前面也有一颗小箭头，点一下把这一支折下去，再点展开；
  没有子标签的行不摆箭头。收起来的只是子标签，父标签自己还在，点它照样把这一支
  的笔记全筛出来——折叠和筛选是两件事。
- **目录多的时候能收起来**：左栏是整库的目录树，平时常去的那几支之外全摊着，一屏
  塞不下。现在每一行前面多一颗小箭头，点一下就把这一支折下去（子目录和更深的那些行一起
  收起来），再点一下展开；底下没有目录的行不摆箭头，免得按了没反应。点箭头只折叠、不等于
  点这一行选中目录。折叠状态只活在这次会话里——存下来反而会在下次打开时对不上记忆。
- **左栏自己也有一个筛**：目录和标签都攒到上百行之后，想找「录音卡」那一支得滚半天，而中栏
  那个搜索框是搜笔记正文的——拿它当目录筛选，人会分不清自己是在搜笔记还是在找目录。现在左栏
  顶上多一格「筛目录和标签」，只筛左栏的目录行和标签行，中栏一个字都不动；命中的那一支连同
  它的上级目录一起留着（不然那一支看着像凭空出现的），清掉就回全量。敲个肯定没有的词时明说
  「没有对得上的目录或标签」，而不是留一片空白；按 Esc 只清左栏这个筛。
- **头部里写着的那条链接，点得开**：`相关: "[[另一篇]]"` 这种写法在笔记头部很常见，
  以前属性区把它当一段普通文字原样摊出来——摆着一条通向另一篇的路，却要自己去左栏翻。
  现在这种整串就是双链的值会做成一颗能点的胶囊，点一下直接跳过去；带小节的 `[[笔记#小节]]`
  也认，`[[笔记|想显示的名字]]` 按那个名字显示。
- **一整摊事，一颗按钮先全勾上**：批量加标签、挪目录、删掉都要先一张张点勾选框，想统一处理
  这一摊几十篇时那是几十次精确点击。现在列表顶上多一颗「全部勾上」，一次把当前这次筛出来的
  卡片全选上；已经全勾着的时候它变成「取消勾选」，再按一下全不勾。只勾屏幕上这一摊、不动库里
  其余的——顺手把另外两百篇也选进来是灾难。
- **贴错标签能一起撕掉**：批量条以前只有「加标签」，想去掉一个贴错的标签得逐篇打开改
  frontmatter，几十篇就是几十次。现在标签输入框旁边多一颗「去标签」，勾几篇、敲个名字、
  按一下，头部那个标签和正文里写着的 `#标签` 一起去掉；同一篇里的别的标签不动。本来就没
  这个标签的那几篇算「处理过了」，不会出现在失败清单里。
- **勾好的那几篇，引用一次抄走**：想把刚筛出来的这几篇贴进另一篇笔记里当索引，以前只能
  一篇篇右键「复制引用」，或者打开每一篇去右栏点那颗按钮。现在批量条上多一颗「复制引用」：
  勾几篇、按一下，一行一条链接抄进剪贴板，链接怎么写先问宿主（Wiki 还是 Markdown、路径写全
  还是写短）。抄完选中不清掉——顺手还想给这几篇贴同一个标签、挪进同一个目录。
- **没成的那几篇，会点名说是哪几篇**：勾十篇一起加标签，其中两篇被别的程序占着、或者路径刚
  被挪走，以前界面上只写「已处理 8」——剩下两篇去哪了没人说，用户会以为都成了。现在服务端
  回来的失败清单会被摊在批量条上面：哪几篇、为什么没成，一条一行，看完点「知道了」收起。
- **按住 Shift 点第二下，连着一整段都勾上**：想给一摊里的十几篇一起挪目录，以前得一张一张
  点勾选框。现在勾了第一张之后按住 Shift 再点一张，中间那一段一起勾上（按当前这次筛出来的
  顺序算，跳过的卡片不会被顺手带进来）；再 Shift 点一下整段取消。勾选框的提示会跟着改口，
  没勾过的时候先教一次怎么连选。
- **卡片上就摆着这一篇的标签**：光看标题、日期和目录，常常想不起这篇属于哪一摊事——标签只按
  条数排在左栏的标签云里，跟具体某一篇对不上。现在卡片底下摆出这一篇的标签，最多三颗、多的
  收成「+N」，点一颗就按它筛，左栏跟着亮（和左栏标签区、属性区里那几颗是同一个动作）。标签多的时候先把它们摊开看一眼，再决定按哪个筛。
- **收起来的那个「+N」，点一下就在原地摊开**：卡片底下最多摆三颗标签，多的收成「+N」——可那个
  「+N」以前只是个数字，想知道这篇还剩哪些标签，只能打开去右栏翻属性区。现在它是一颗按钮：点一下
  整行换行摊出全部标签、按钮自己改成「收起」，再点收回三颗。摊开只是把话说完，不是按它筛（左栏不会
  亮起来），也不会顺手把这一篇打开。
- **面板开不出来的时候，得说一句**：点了大脑图标没反应、屏幕上还是原来那样，是最难查的一种——
  调用方拿到的是一条没人接的拒绝，日志里也什么都没有。现在打开面板这一步失败时会弹一句说明
  （带上真正的原因），同时往插件目录的 `boot.txt` 里记一行，下次再碰上至少知道卡在哪一步。
- **搜索卡片上那行「它引用了谁」，收起来的那几处也点得开**：搜索时卡片底下会列出这一篇引用了哪几篇，
  最多四颗、多的收成「+N」。那个 +N 以前也只是个数字——想看完整名单只能点进去翻。现在点它就地把剩下
  的引用一起摊出来、按钮改成「收起」，再点收回四颗。摊开不跳走，也不会把这一篇打开。
- **卡片上那个目录，也点得动**：看到一篇在「随手记/录音卡」底下，想知道同一摊里还有哪几篇，以前只能
  回左栏一层层展开去找。现在卡片 meta 行里那个目录是一颗按钮：点一下直接按这个目录筛，左栏跟着亮，
  顶上摆出一颗点得掉的筛选胶囊——和点标签是同一个动作，也不会顺手把这一篇打开。
- **热力图上哪一天写过东西，点一下就只看那一天**：那颗格子以前只有一句悬停提示，知道那天写了
  几篇，却打不开那几篇——想看只能去文件列表里按日期一页页翻。现在写过字的那一天是一颗按钮：
  点一下按这一天筛，左栏顶上摆出一颗点得掉的日期胶囊，再点同一颗格子就取消。空日不摆按钮——
  点下去只会筛出一屏「没有笔记」，那是噪声。按日期筛时会把目录和标签的筛选一起让开，否则两个
  条件一叠加常常是空的，人会以为那天什么都没写。
- **卡片上那个日期，也点得动**：和热力图是同一个动作，只是从「这一篇卡片上」出发——看到一篇是
  10 月 22 日写的，想知道同一天还写了什么，不用先回热力图找那颗小格子。点一下按这一天筛，左栏顶上
 摆出日期胶囊，再点同一篇的日期就取消；和点目录、点标签一样，不会顺手把这一篇打开。
- **版本历史里那一版差多少，打开就说**：点开一版以前只能看正文长什么样，是多了几段还是改了几个字，
  得自己一行行比对。现在头部紧跟保存时间写着「恢复后多 3 行 · 少 1 行」，一行不差时说「和现在一样」。
  方向是「从现在换成这一版」，所以「少」就是恢复之后会变短。极端大的文件退回按行计数估算，
  不会为了算这个把面板卡住。
- **搜索框记得住库里的目录和标签**：`tag:` / `dir:` 是省时间的写法，可目录名到底带不带斜杠、
  标签有没有嵌套，全凭记忆——记错一个字，搜出来就是空的，还不知道是自己打错了。现在敲到
  一半就把库里已有的目录名和标签名摆出来：`dir:随` 只摆目录，`#读` 只摆标签，裸词两边都摆，
  打头的排前面。上下键挑、回车补进去，Esc 先收候选（不会把已经敲好的词一起扔掉）。
- **哪些双链还是空的，一眼看得出来**：一篇笔记里十几个双链，以前它们和真链接长得一模一样，
  点下去才知道哪个指向的笔记还没写——想知道「我还有哪些没补」得挨个点。现在指不到的链接
  暗一档、下划线改成虚线，悬停直接说「库里找不到「某某」这篇笔记」；点下去仍会明说一句，
  不会静悄悄没反应。判定用的是嵌笔记那一套口径（文件名、标题、别名、宿主索引），不另起
  一套规则，免得两边说法不一。
- **出链里哪一条还是空的，同样看得出来**：篇尾那排出链是这一篇自己写下的名字，写错一个字
  或者那篇还没开始写，在胶囊上和真链接一模一样。现在指向不存在的那些暗下去、带一圈细边框，
  悬停说「库里找不到「某某」这篇笔记」；判定和正文双链共用同一个解析函数，不会出现「正文里
  标着空、出链里却是亮的」这种自相矛盾。整条藏起来不行——「想写但还没写」本身就是要看见的。
- **读到一半想知道这篇在库里的哪儿，点路径就行**：笔记头那行路径以前只是字，
  想看它在库里的位置得回列表、右键、再找「在文件列表里定位」，绕一圈。现在这行
  字自己就是入口——点一下（回车、空格也行）就把路径交给宿主，文件列表在它旁边展开。
  宿主没这个接口时它退回纯文字，不留一个点了没反应的样子。
- **拖到左栏那个目录上，就挪进去了**：把一篇从 A 目录挪到 B 目录，以前得先勾选、
  再在批量条里挑目录；而拖动这件事本身已经把目标指得很清楚了。现在把列表里的卡片
  直接拖到左栏某个目录行上，松手就挪过去，那一行会先亮起来告诉你「放这儿」。同一份
  拖动还带着一条给宿主编辑器用的链接——拖到面板外面仍然是插一条链接，只有落在左栏
  目录上才算挪动。从宿主文件树拖进来的文件不受影响，那还是「导入」。正开着的那篇被
  挪走时笔记头里的路径会跟着换掉，否则下一次保存会写回旧位置、旧目录里凭空多一个副本。
- **拖到左栏那个标签上，就贴上了**：给一篇笔记加标签，以前得勾选、再在批量条里敲标签名。
  同一份拖动现在也能落在左栏的标签胶囊上——松手就给这一篇贴上那个标签，胶囊先亮一圈边框
  告诉你「放这儿」。和拖到目录上不同，这是「加一横」不是「搬走」：笔记留在原地，只是头部
  多一个标签，正开着的那篇当场长出新标签、不用重开一次。
- **删掉的东西，放回你指定的那个目录**：回收站里恢复一篇时，文件只能落回库根——因为
  回收站里的文件名只留了名字，原目录没记下来，于是「恢复」等于把文件从一堆同类里挑出来
  再自己挪回去。现在回收站说明行下面有一行「恢复到哪个目录」，敲两个字就有目录候选，
  选中之后按「恢复」就直接落进去；留空还是老样子放库根。同名的不覆盖，照旧加后缀。
- **删之前先看一眼，不用先恢复出来**：回收站里只剩一个文件名，想确认「是不是这一篇」以前
  只能先恢复出来看，看错了还得再删一次。现在每一行多一颗「看一眼」，点开就在原地摊出那篇的
  开头一段；太长就只摊前面一段，尾巴写清还有多少字没展开。再点一次收回去，一次只摊一篇。
  只是读，不碰文件——看完想恢复还是想永久删，都不受影响。
- **删之前先问一句「还有谁提到它」**：断链长在别人的正文里，删的人看不见——删完之后才
  发现另外几篇里那句引用变成了点不动的死链。现在按删除会先反查一遍，有谁提到这一篇就
  把篇名点出来、说清删掉之后那几处会断，问一句「还是要删 / 先不删」。一篇都没提到它时
  不弹这一问，还是原来那样删进回收站。反查查不出来时不拦着——诊断失败不该拦住用户
  删自己的笔记。
- **批量删之前也先看一眼「这几篇里谁被人提到过」**：单篇删早就会反查，批量删却只问一句
  「确定吗」——勾了十篇里有三篇在别人正文里被引用，删完那三处就变成点不动的死链，
  删的人事先一点提示都没有。现在批量删之前先把这一批一次问清（一遍全库，不是一篇一遍），
  有被人引用的就把篇名点出来、说清有几篇、那几处链接会断，问一句「还是要删 / 先不删」；
  一篇都没被提到时还是原来那句「确定把这 N 篇移到回收站」。反查查不出来时不拦着。
- **目录不是空的也能删，但笔记是进回收站、不是真没**：以前删目录只肯删空目录，撞上「这个目录
  里还有 12 篇」就只剩一条路——先把它们一篇篇挪走。现在右键删目录会先数一遍，确认框里把
  「里面还有 12 篇笔记、3 个子目录」说清楚，旁边多一颗「连里面的 12 篇一起删」。点它之后
  每一篇照旧先进回收站，删完提示也说「目录已删，12 篇在回收站里」——一起删不等于真删，
  想反悔还是能一篇篇恢复回来。有一篇移不进回收站就整个停下、目录留着，不留半个现场。
- **回收站里攒了一堆，一次挑几个一起动**：一行行点「恢复」是纯体力活，更要命的是「放回哪个
  目录」这件事本来就得一次说清——分开点等于把同一个目录名敲十遍。现在回收站每一行左边有一颗
  勾选框（一直摆着，不像笔记卡片那样要悬停才显形），勾上几个之后上头出现一条批量条：报出
  「已选 3 个」，能「全选」「取消选择」「恢复这几个」「永久删除这几个」。恢复走
  `POST /getnote/trash/restore/many`，一个请求把几个文件按同一行填的目录放回去，同名照旧不覆盖、
  加后缀；永久删走 `/trash/purge/many`，先问一句「无法撤销」。有几个没成时提示里分开报
  「已恢复 2 个 · 有 1 个没能恢复」，不把半成功说成全成。恢复完勾选当场清空、批量条收起。
- **引用某一节，不用自己拼链接**：想引用长笔记里的某一节时，得自己拼 `[[笔记#小节]]`——
  小节名少一个字就是一条点了没反应的死链，而且不报错。现在大纲里每一行右边有一颗小按钮
  （鼠标停在那一行才显形，不占地方），点一下就把指向这一节的链接抄进剪贴板。怎么拼仍然问
  宿主：用户在 Obsidian 里选了 Wiki 链接还是 Markdown 链接、路径写全还是写短，都由它决定；
  问不到才退回最通用的 `[[路径#小节]]`。点标题本身还是「跳过去」，两件事分开。
- **搜完按回车，就进最该看的那篇**：搜出来之后还得把鼠标挪到第一张卡上点一下——
  搜索这条路上最后一段体力活。现在搜索框里有字时按回车，直接打开排在最前面的那篇
  （搜索结果是按相关度排的，排头那篇就是最该看的）；Esc 把搜索框清空、退回整份列表，
  不用先把光标挪到那个叉上。空搜索框里回车什么都不做——那时「第一篇」只是整份列表的
  头一篇，打开它太意外了。输入法还在组字时回车照样是上屏，不会把笔记打开。
- **一串词要连着、不想要的能排掉**：搜索框原来只认「空格分隔、全部命中」——
  搜「开会 记录」，两篇里这两个词各出现一次也算命中，想找那一次连着的会议没法说清；
  想排除录音转写也没处写。现在引号把一串词绑成一个（`"开会 记录"` 要连着出现），
  前面加减号就是不要它（`会议 -录音`）。两个都在服务端拆，面板只是把整串原样递过去，
  所以搜索框里那行提示也一并写上了这两种写法。
- **篇尾看得见这一篇多少字、大概读几分钟**：读之前想知道「现在有没有时间读完」，
  读长逐字稿时想知道「还剩多少」，以前只能切进编辑态看一眼草稿字数。现在阅读态篇尾
  也有一条：多少字、约几分钟读完。字数口径与编辑态那条一致（中文按字、西文按词），
  时间按每分钟三百字算、不足一分钟也报一分钟——报「约 0 分钟」等于没报。
- **搜索框里有字，右边就有一颗清空**：打了半截才发现想搜的是另一件事，以前得把光标挪回去、
  按住退格一路删，或者按 Esc——而 Esc 在候选摆着时只收候选，要按两下才清得掉。现在有字就摆
  一颗 ×，点一下清空、列表退回整份、光标还在框里好接着敲；空框上不留这颗按钮，免得按了没反应。
- **搜出来的这一摊，一次抄成一段清单**：想把「这次找到的这几篇」发给别人，以前只能一篇篇右键
  「复制引用」。现在搜索框那一行多一颗复制按钮：一行一篇，写名字和位置（只写名字的话，重名的
  那几篇分不出来）。一条都没搜到时不摆它——空清单没有可抄的。
- **搜过的词记在搜索框下面**：像「录音卡」这种词一周要打好几次，以前每次都得从零敲一遍，
  隔一天回来连上次搜的是「录音卡」还是「录音卡片」都想不起来——而搜过什么只有你自己知道，
  宿主那边没有这个信息。现在搜索框空着的时候，下面摆着最近搜过的几个词（最多八个，存在本地，
  重启 Obsidian 也在）：点一颗就填回框里、当场又搜一遍；旁边一颗 × 一次清干净。正搜着的时候
  这一排收起来——摆一排别的词只会把人往岔路上带。边打边搜的中间态（「最近」「最近搜索」）不会
  被存进去，只留停手之后那个整词。
- **搜完告诉你扫了多少篇**：搜「录音」只回来四十篇的时候，人分不清是库里就这么多、还是
  被条数上限截了——两种情况下一步该做的事正相反（放宽词还是收窄词）。现在搜完在提示那行
  下面多一句「扫了 N 篇，对上 M 篇」；真被截了就再补一句说停在条数上限、后面还有没扫到的。
- **这次到底按什么在筛，摆出来给你看**：搜索框里敲 `tag:录音卡 dir:随手记 会议 -录音` 这样一串，
  敲完就滚走了，界面上只剩一行教「怎么写」的灰字，没人回答「我这次到底按什么在筛」。现在把这串
  拆成几颗胶囊摆在下头：限定词、正文词、排除词各一颗，排除词划掉、前面还有一行「这次按这些筛」。
  想去掉其中一个限定词，点掉那一颗就行——那一段从框里消失、当场重搜一遍，不用清空重打。
  只敲一个普通词时不摆：一颗胶囊重复框里那两个字纯属噪声，有拼接或有限定词时才有拆开看的必要。
- **搜不到的时候，那一屏也得说清楚**：以前搜不到东西，中栏干脆是一片空白——连「没有匹配」
  四个字都没有，看着像面板卡住了。现在搜不到会说清是没有匹配、建议换个词或者用 `tag:` `dir:`
  缩范围，底下还给一颗「清空」一键把搜索词抹掉；筛着一个空目录时同理，说清是这一支还没有笔记，
  给一颗「清掉筛选」把目录和标签一起撤掉。空列表那一屏不再只有「新建」一条路。
  连笔记库都还没指过的时候也一样：以前照旧说「这个目录还没有笔记」，可根本还没有目录；
  现在直说还没有本地笔记库，并给一颗「去设置里挑个目录」直接跳到设置页——没有库的时候
  「新建」和「清掉筛选」都是空转的，所以那两颗这时候不摆。
- **搜到哪一行就落到哪一行**：搜索卡片上列出的命中行（带行号）现在自己也能点了——点下去
  直接打开那一篇并滚到那一行，不用进去再搜一遍那个词。锚用的是那一行的**文字**不是行号：
  搜索是磁盘上那一刻算出来的，你刚在别处改过这篇、行号一挪，按行号找就指到别的段落去了。
  行号还留着，是给你判断「值不值得点」用的。那一行找不到时安静地停在篇首——多半是刚被
  你改掉了，为这个弹一条错误比不吭声更吵。命中行里的词还做了标记：整行灰字让你自己再
  找一遍，等于白搜；`tag:` / `dir:` 这类限定词不去染正文（它们本来就不出现在那一行上）。
- **引用一段就嵌一段**：正文里写 `![[另一篇笔记]]`，那一篇的正文会连同标题一起嵌在
  这里，左边一道竖线分清楚哪段是别人的——跟宿主里看到的一样。只嵌一层：嵌进来的那篇
  里再嵌一篇时留成文件名胶囊，两篇互相嵌入也不会一路读下去；PDF、录音这些附件和解析
  不出来的名字仍然是文件名，不会拿去当笔记读。点嵌入框头上的名字能跳到那一篇。
  `![[笔记#小节]]` 会停在那一节上（不是从头显示），`![[#本节]]` 就是「滚到这一篇的这一节」，
  `![[笔记#^abc123]]` 只摆出挂了那个 id 的那一段（不是整篇嵌进来再滚过去）。
- **别名也算数**：`aliases: [读书笔记]` 之后，`[[读书笔记]]` 在面板里也指得到那一篇——
  以前只比文件名和标题，同一个链接在 Obsidian 里点得开、在面板里报「库里找不到」。别名排在
  最后一级：撞上真实文件名或标题时，真实的那一个更该赢。
- **正文里写的 #标签 也算数**：标签能写两处——头部的 `tags:`，和正文里随手一个 `#生活`。
  宿主两个都认，面板以前只认头部：同一个标签写在正文里，标签云里没有它、点它也筛不出这一篇，
  可写在头部就一切正常。现在两边合起来算，标签云、左栏筛选、`tag:生活` 搜索都能命中；删标签
  和改标签名会连正文里那个一起改掉（只改头部的话，删掉的下次扫描又冒出来、改名后会同时出现
  新旧两个）。围栏代码块、行内代码、`# 标题`、URL 里的 `#片段`、纯数字都不算标签。
   正文里那串 `#生活` 也做成能点的胶囊：点一下就在左栏筛这个标签，跟笔记头属性区那几颗是
   同一个动作（没接筛标签的去处时只上色，不给一个点了没反应的按钮）。
- **引用块也认得宿主那套 callout**：`> [!warning] 别在周五上线` 这种块在 Obsidian 里是
  一块带图标、带配色、能折叠的提示框，以前在面板里只是普通引用——`[!warning]` 那几个字符
  原样显示出来，跟你写的「别在周五上线」混成一行。现在图标、标题、正文各归各位，警告是黄的、
  失败是红的、提示是绿的；类型名是自由的，认不出的也照样把标题摆出来，只是配色走中性那套
  （认不出就退回普通引用的话，那串字符又会冒出来）。`[!note]-` 这种带减号的默认收起，点标题
  才展开，跟你写的一样。
- **删除线、高亮、注释按宿主那套认**：`~~划掉~~`、`==高亮==`、`%%注释%%` 都是 Obsidian
  自己的写法，标准 Markdown 里没有。以前三种都会连符号一起原样露在界面上，看起来像正文写
  错了；现在删除线真的划掉、高亮真的标黄，注释**一个字都不露**——宿主里注释是整段不存在，
  不是小字也不是灰字，留成灰字反而会让人以为自己写的没被注释掉。注释还不只是「不显示」：
  它不参与标签云（注释里随手写的 `#草稿` 不会冒出来）、不参与摘录、不算反链、也不会被断链
  体检报成死链——这些都是宿主的口径，少一样就会出现「在 Obsidian 里正常、在面板里冒出一堆
  奇怪东西」的错位。
- **一段话就是一段话**：宿主里段落中间敲一个回车是「软换行」，接着往下写还是同一句；
  行尾敲两个空格（或者一个反斜杠）才是真的断行。面板原来每个换行都断，同一段在 Obsidian
  里是一行话，搬过来被切成好几行，版式看着像两篇东西。
- **图片写多大就多大**：宿主里 `![[图.png|300]]`、`![[图.png|300x200]]` 是给图定尺寸。
  面板原来把竖线后面那串当显示文字（图片本来也没有显示文字），图还是原样大小、还被缩略图
  那条高度压住。现在按写的来。
- **脚注也有上标**：宿主里 `正文[^1]` 配篇尾的 `[^1]: 注解` 是一条脚注。面板原来把定义
  行当普通段落原样显示，读者会看到一串 `[^1]: …` 混在正文中间。现在正文里只留一个能点的
  上标，注解收在篇尾一小块里（缩进的续行会接上）。看完注解想回到原来那一句接着读，
  点一下篇尾那一行就跳回去——正文可能有好几屏长，往回找是纯体力活。
- **提示框里的待办不会勾错**：待办是按「第几个」落盘的（同一篇里两条「喝水」很常见，
  按文字改会一次改两行）。宿主那边逐行扫、跳过代码围栏，提示框里那几行开头是 `>`，
  压根不算第几个；面板原来把提示框里的一起数了进去，于是用户勾的是提示框里那一条，
  落到盘上改的却是正文里另一条——勾错了还看不出来。现在两边口径一致。
- **`[文字](笔记.md)` 也是库内链接**：宿主里除了 `[[双链]]`，普通 Markdown 链接写成
  `[会议纪要](随手记/会议.md)`、`[小结](#小结)` 也往库里跳。面板原来一律当外链、新开窗口，
  点下去什么也不会发生（库里没有那个相对地址），看着就像链接坏了。现在认得出来的交给同一套
  解析（`#小节` 就是本篇的那一节），外站、邮件、附件仍然当外链。
- **块引用也认**：宿主里 `一段话 ^abc123` 给这一段挂个 id，别处写 `[[笔记#^abc123]]`
  就能直接指到这一段。面板原来把它当成小节名去找标题，永远找不到，还弹一句「这一篇里
  没有 ^abc123 这一节」——链接没坏，是我们的理解坏了。现在按 id 找块、记号本身也不露在
  正文里；嵌进来的时候也只摆那一段，不是整篇摆出来再滚过去（滚过去之后看到的还是一整篇，
  分不清哪一句是被引的那句）。
- **编辑的时候脚下有字数和办法**：编辑区底下一直空着，用户不知道按什么保存，也不知道
  自己写了多少。现在那条写着字数（中文按字、西文按词，和宿主一个口径）和「Ctrl+S 保存 ·
  Esc 取消」，改一个字它就跟着动。清单里按回车也接上了：光标停在「- 一条」末尾敲回车，
  下一行自带同样的记号（有序列表自动加一，`- [ ]` 接着是 `- [ ]`），接着写就行；空条目
  敲回车是「这一条不写了」，把那行记号收掉。光标停在行中间时不管——那一下是「把这行拆成
  两条」，替用户补个记号反而把他写了一半的句子劈开。`Tab` 也不再是把焦点挪走：它把光标
  所在的整行往右挪两格（`Shift+Tab` 收回来），缩进的是整行不是光标处——在清单里缩进的
  意思就是「这一条挂到上一条底下」，在句子中间插两个空格只会把那句话顶出一个洞；空行
  不补空格，免得下次打开看见一串看不见的空白。加粗也不用自己手打星号了：选中几个字按
  `Ctrl+B` 包成 `**这样**`、`Ctrl+I` 是斜体、`Ctrl+Shift+X` 是删除线，选区跟着记号一起挪，
  接着还能改；再按一次是取消——认得出「这一对已经包在外面了」，把它剥掉，而不是再套一层
  （套两层在 Markdown 里不会变粗，只会变成字面的星号）。没选中字时插一对、光标落在中间，
  接着敲的字就是加粗的。
- **列表能按名字排了**：左栏的目录和标签早就能切「按修改时间 / 按名称」，中栏那列笔记
  卡片却一直是服务端给什么顺序就是什么顺序（按修改时间倒序）——想在几十篇里按名字找一篇，
  只能去搜。现在搜索框右边也有一个同样的开关，点一下在「最近改的在前」和「按名称」之间切，
  切完记在本地，下次打开还是这个顺序。按名称用的是中文排序规则，不是按码位排；搜索的时候
  这个开关收起来——那边的顺序是相关度排的，换成本地排序反而把最该看的那篇挤下去。
- **读长笔记时当场就能找**：以前想找一句话，得先离开这一篇、回到搜索框输词、再点命中行跳回来，
  找一句话的代价是走三趟。现在笔记头上有一颗放大镜，点开就在这篇里找：回车跳到下一处、
  Shift+回车回到上一处，Esc 收起。只把视野挪过去，不弹浮层也不标高亮——找的是「那一句在
  哪」，不是「把这一篇变成搜索结果页」。判断的是「哪个块已经滚到容器顶上」，留 12px 余量，
  刚跳过去的那一块不会被当成「还没到」而原地打转。一处都没有时说「这篇里没有「某词」」，
  已经有词但走到头了说「已经到头了」——两件事分开说，用户才知道是该换词还是该往回翻。
- **找的时候知道自己走到第几处了**：查找条以前只有「下一处」一个动作，一篇长笔记里反复按
  回车，走到第几处、还有几处没看全凭记忆。现在输入框右边摆着「2/7」，按到最后一处说完
  「已经到头了」就停在那儿不动；改了词就把旧数字收掉——那是上一个词的进度，留着只会误导。
  编辑态一样报，只是数的是 textarea 里那一段。
- **读的时候能往回退一步**：从 A 点进 B、又从 B 跳去 C，想回 A 得先退回列表、再翻一遍
  找到它——宿主里 Alt+← 就回去了，面板里没有这回事。现在每打开一篇都记进一条路径栈（最多
  40 篇，多了丢最早的），Alt+← 回上一篇、Alt+→ 再走回去，笔记头路径左边也摆了两颗箭头，灰着
  就是走不了。从栈中间往回退之后再点开别的一篇，前面那截「前进」当场作废——和浏览器一样，
  否则「前进」会跳到一条已经不在路径上的分支去。只记路径不记正文，走回去还是重新 `/read`
  一次，拿的是当下真实的那一版；有没保存的草稿时先问一句，别把刚写的半句冲掉。
- **接着看下一篇，不用退回列表再找**：路径栈只认「我点过的顺序」——从搜索结果里点进第 7 条，
  想接着看第 8 条时栈里根本没有它，只能退回列表从头找。现在笔记头路径左边多两颗箭头，按的是
  **这次筛出来的列表顺序**，和屏幕上看到的顺序一致；悬停直接写着上一篇/下一篇是哪一篇。阅读态
  脚下还报一句「第 7 / 40 篇」，读到中间时知道还剩多少、到底了没有。走到头那颗就收起来，不留
  一颗按了没反应的按钮。
- **Ctrl+F 就能找，不用先找鼠标**：查找条以前只有笔记头上那颗放大镜能叫出来，键盘按 Ctrl+F
  什么都不发生——面板级那套快捷键在输入框里就放手了，它自己也只认 Ctrl+K 和 Ctrl+N。可宿主
  的阅读视图里 Ctrl+F 是肌肉记忆。现在阅读态按下去就把查找条叫出来、光标直接落在输入框里，
  再按一次也不会把它关掉（那是「叫出来」的手势，不是开关）。编辑态按下去找的是正文里那一段
  字：那时候正文根本没渲染，挪的是选区不是视野，命中的那一行会滚到视野中间，你才知道它是往
  上还是往下去了。Esc 收起时编辑态顺手把焦点还给正文——不然接着敲的字全进了那个已经藏起来
  的框里，看着像编辑区坏了。编辑区底下那行提示也写上了 Ctrl+F。
- **写到一半没了，下次还能捡回来**：面板的编辑器是草稿式的——正文只活在内存里，切页签、
  关窗口、宿主重载插件都会一起带走。写了一整段、手滑按了刷新，那是真丢了，连个「撤销」都没有。
  现在编辑态边写边往本地留一份（400ms 防抖，只留最近 5 篇、每篇封顶 20 万字：这是救急用的，
  不是版本历史，不封顶会让一篇长笔记把浏览器的配额吃掉大半）。下次打开同一篇，如果磁盘上的
  正文和那份草稿对不上，正文上方就提一句「上次写到一半没存（时间）」并摆「接着写 / 丢掉」：
  接着写会把草稿填回编辑区，丢掉就清掉。存好了、按「取消」、按 Esc，草稿都跟着消失——不然下次
  白问一句「上次没存」，而其实早就存好了。提醒条只在阅读态摆，正在写的时候再提一句只是噪音。
- **Ctrl+E 存好就退出**：看完一段想改几个字，改完还得去笔记头找「保存」再找「取消」，两次鼠标
  都花在同一件事上；宿主里 Ctrl+E 就在编辑和阅读之间来回切。现在面板也认这个键：阅读态按下去
  进编辑，编辑态按下去存好再退。存好再退而不是直接退，是因为面板的编辑器是草稿式的——直接退出
  等于把刚写的丢掉，而按下这个键的人想说的是「我看完了」。没改过就不白写一次盘，存不下的时候
  也照样退出（半句留在草稿里，不会因为存失败把人锁在编辑态）。
- **读到哪儿，回来还在那儿**：长笔记读到第三节、切去回个消息，回来又从第一行开始，得自己
  再翻一遍。现在每篇各记各的位置，换回来就放回去（最近翻过的 40 篇都记着，多了丢最旧的）。
  没记过的那篇从头开始——正文容器是同一个 DOM 节点，不清的话会停在上一篇读到的地方；翻回
  顶上就记 0，不会留着上一次的位置等你下次「惊喜」。记位置不记正文，回来还是要走一遍
  `/read` 拿当下真实的内容。
- **双链不用背路径**：在编辑区里敲 `[[`，底下就摆出库里名字对得上的那几篇——名字打头
  的排在前面，用上下键挑、回车（或 Tab）补上，也可以直接点。以前写双链得凭记忆把路径一字
  不差打对，打错一个斜杠就变成断链，还得回头去翻列表找那篇叫什么。重名的（两个目录下各有
  一篇「周报」）插进去的是整条路径，否则 `[[周报]]` 会指到另一篇去；名字一条都对不上时
  才退回比整条路径，不会因为目录名撞上就把整个目录列出来；一条都没有就什么都不弹。
- **筛了什么，界面上写着**：在左栏点一个目录、点一颗标签，中栏就只剩一部分卡片，但界面上
  一直没有留下任何「现在筛的是什么」的痕迹——切去别的目录再切回来，人会以为笔记丢了，
  或者以为扫描出了问题。现在中栏顶上会摆出当前的筛选：目录一颗胶囊、标签一颗（带井号，
  颜色也不一样），悬停说清点一下会怎样，点掉就退回去；两颗都清掉，整条自己收起来，不占
  平时的位置。它们和左栏的高亮是同一份状态，从哪边点都算。
- **按 ? 就能看见都有哪些键**：面板里能按的键散在各处——编辑区底下那行提示写着几个，
  按钮的悬停说明里各写一个，谁也不会把十几颗按钮一个个悬停过去。于是有人用了半年都不知道
  按 J/K 能上下翻、Alt+← 能回上一篇。现在按 `?`（或者点顶栏那颗问号）就摊开一张速查表：
  左边是键位、右边说按了会怎样，十几条一次看全；再按一次 `?`、按 Esc、点空白处、点「关闭」
  都能收起来。焦点在输入框里时按 `?` 不弹——那时用户是要打问号这个字。
- **标签也能分层看**：标签云以前是一颗颗平铺的胶囊，父标签「读书」和它下面的「读书/摘抄」
  并排摆着，看不出谁属于谁；同一份前缀还在每颗胶囊里重复一遍，一屏能塞的标签少了一半。
  现在按斜杠摊成层级：父标签一行、子标签缩进去一层、边框换成虚线，父标签上的数把子标签
  一起算进去。点父标签把子标签下面的笔记全收进来，点子标签只筛它自己那一篇；悬停能看到
  完整路径，因为摊平之后一行里只看得到最后一段。
- **标签也不用背**：双链能补全之后，标签成了唯一还得凭记忆敲的东西——而它比双链更
  容易写错：写错一个字不会报错，只会在标签云里多出一颗只有这一篇才有的孤零零的胶囊，
  过两天自己也认不出哪个才是「正牌」的那个。现在编辑区里敲 `#` 再打两个字，底下就摆出
  库里用过的标签，打头的排前面，上下键挑、回车（或 Tab）补上，也可以直接点。补的是库里
  真用过的词，凭空敲一个没人用过的新标签照样能敲完，只是没有候选——这恰好也是防手滑的
  那一层。判断得很克制：`C#` 这种紧贴着字的井号不算、`## 标题` 不算、`[[笔记#小节]]`
  里那个井号是在补小节也不算；标签不像双链，补完不用再加右括号。
- **大纲上亮着「现在读到哪一节」**：长笔记滚到一半，用户会想确认自己看的是第几节，以前
  大纲里一条都不亮，只能自己数。现在正在读的那一节左边有一道竖线、文字换成主色——从大纲
  点过去的当然算，自己用滚轮往下翻也跟着变（判断的是「哪个标题已经滚到容器顶上」，留
  24px 余量，刚贴上去就算在这一节里）。只加粗上色、不动背景，否则和「鼠标正停在这」抢视觉。
- **表格的对齐标记也算数**：`| :--- | ---: |` 这行分隔符里的冒号在 Obsidian 里是「这列
  靠左 / 靠右 / 居中」。面板原来一律靠左，一份金额右对齐的表格搬过来会全部贴到左边，位数
  不一就完全没法对账。现在三种都认，没写冒号还是默认对齐。
- **属性就写在笔记头上**：frontmatter 里的 tags、aliases、你自己加的字段，阅读时摊在正文
  上方一块「属性」里——以前这块完全不显示，你在 Obsidian 里写的标签回到面板里一眼都看不到，
  还以为没存上。标签做成一颗颗可点的胶囊，点一下等于在左栏筛这个标签；空值的键（`aliases: []`
  这种写了等于没写的）不占行，整篇没有头部时这块压根不出现。
- **拖进来就是附件**：把图、录音、PDF 拖到笔记正文上，或者截图之后直接 Ctrl+V，文件会
  存进这篇笔记旁边的 `asset` 目录、正文里自动多一行引用——跟宿主里做的是同一件事。文件名
  带上笔记主干前缀（不然附件区认不出来，你会以为没存进去又拖一遍），同名的不覆盖、自动加
  后缀。有没保存的草稿时只改草稿不落盘，不替你保存半句话；没草稿就直接存好。
- **跟着宿主一起看**：命令面板里一条「在 Obsidian 里打开当前笔记」，把正在 Obsidian 里
  读或改的那篇切到面板里——反链、同步状态、历史版本、附件都在那边。想要它一直跟着也
  可以：设置页里勾上「面板跟着我翻」，之后你在 Obsidian 里翻到哪一篇，开着的面板就切到
  哪一篇。这个开关默认关着（面板自己动，得你点头）：面板没开着时不会替你打开它，不在
  「得到大脑」目录里的笔记也不会跟。
- **模板能摊开看全文**：设置页里每个自定义模板那一行右边多一颗「看全文」，点了就在原地
  摊出完整骨架（列表里只露两行，周报、复盘那种几十行的根本看不出当初写了什么），再点一下
  收起；只有标题的模板明说它只有标题，不摊一个空框。一次只摊一个——摊开两三个，想找的那
  一个反而更难找。
- **字号是这一篇的事，不是全库的事**：笔记头上那三档「小 / 标准 / 大」原来一刀切，一篇小字
  扫描件调到「大字」之后，回头看普通正文就嫌挤；调回标准，那篇扫描件又变小了。现在按篇记：
  这一篇调大了，换一篇还是它自己那档，回来还是大的。调到「标准」等于没单独调过，那笔记录
  顺手抹掉，不让它越攒越长。
- **空态里那颗按钮是真的**：右栏没打开笔记时那句「也可以点「新建」写一篇」，原来只指着顶栏
  那颗「+」，空态里什么都没摆。现在话说到哪儿按钮就摆到哪儿，点一下就地建一篇并打开。

## 安装

### 从社区市场安装

Obsidian 设置 → 第三方插件 → 浏览 → 搜「得到大脑」。目录里的条目还在审核队列里时，
用下面的手动方式。

### 手动安装

1. 下载 `main.js`、`manifest.json`、`styles.css`，以及 `card/`、`locale/` 两个目录。
2. 放进 `<你的库>/.obsidian/plugins/getnote-brain/`。
3. Obsidian 设置 → 第三方插件 → 关闭安全模式 → 启用「得到大脑 Get笔记」。

> `card/` 是录音卡用的 Python 桥脚本，`locale/` 是界面文案。**这两个目录必须一起放**，
> 缺了不影响本地笔记功能，但录音卡与多语言会不可用。

### 从源码构建

```bash
npm install
npm run build      # 产出 main.js，并把 card/ 与 locale/ 复制到插件根
npm test           # 946 项离线测试（需 Node ≥ 22，jsdom 31 依赖 Node 22 的 zstd API）
npm run check:market  # 上架条件自检：id/name/description 的规矩、版本三处一致、有没有泄露
```

开发时用 `npm run dev` 进入 watch 模式。

推上去之后 GitHub Actions 会跑同一套测试（`.github/workflows/test.yml`）：
`npm ci` + `npm test`，Node 22 / Ubuntu。CI 最后一步还会重新构建一次再
`git status --porcelain main.js card locale`——构建产物和源码不一致（改了源码忘重建、
或重建后忘提交）会直接判失败，免得用户下到的是旧代码。最后一步跑
`npm run check:market`，把社区目录的硬性规矩（id 不能带 obsidian、description 不能带
Obsidian 且必须以标点收尾、版本三处一致、仓库里没有个人信息与真凭证）在提交时就查一遍，
免得等到目录审核驳回再重走一轮。

打标签即发布（`.github/workflows/release.yml`）：`git tag 0.1.0 && git push --tags`
会重跑测试、打包出 `getnote-brain-<tag>.zip`（含 `main.js` / `manifest.json` /
`styles.css` / `card/` / `locale/`）挂到 Release 上，可以直接下载解压进插件目录；
同一份 Release 里还单独挂了 `main.js` / `manifest.json` / `styles.css` 三个文件，
社区目录校验和 Obsidian 的自动更新都按这三个文件取，少一个就更新不了。

## 使用

启用后左侧边栏出现大脑图标，点开即面板；也可以用命令面板：

- `得到大脑：打开面板` —— 在当前工作区打开。
- `得到大脑：在新窗口打开` —— 弹独立窗口，适合双屏。

**第一次用请先设置笔记目录**（设置 → 得到大脑）。默认是库根下的 `得到大脑/`，
你可以改成库内任意目录，插件会自己建。

### 关于本地服务

面板里的图片与音频是浏览器原生资源加载（`<img>` / `<audio>`），
需要真实的 HTTP 地址才能支持 Range 拖动播放，所以插件启动时会在
`127.0.0.1` 上开一个**只绑回环地址**的小服务（端口由系统分配，会记住上次的）。

- 它只监听 `127.0.0.1`，局域网内其它机器访问不到。
- 关闭插件即关闭服务。
- OAuth 登录的回调也走这个地址，所以授权时浏览器要能访问本机。

## 与 DSH 版的差异

| | DSH 版 | Obsidian 版 |
| --- | --- | --- |
| 宿主 | 挂在 DSH `webServer` 的 `/getnote` 前缀路由 | 自带 `127.0.0.1` 回环服务 |
| 库的选择 | 可指向任意绝对路径 | 只能选当前库内的子目录（写入走 `app.vault.adapter`） |
| 界面 | React 三栏，注册进 DSH 的 slot 系统 | 同一个面板（Preact + compat 层），装进 Obsidian `ItemView` |
| 主题 | `--dsw-alias-*` 变量 | 同一批变量映射到 Obsidian 的 `--background-primary` 等 |
| 录音卡 | 同 | 同，但必须 `isDesktopOnly`（要起子进程） |

之所以「不能直接复制」，主要就在这几层接线；核心逻辑（vault / archive / history /
cloud-sync / openapi / biji / card 与 Python 桥）是同一份代码，测试也是同一套。

## 目录结构

```
src/
  main.js            插件入口：加载设置、起服务、注册视图与命令
  host/server.js     127.0.0.1 回环 HTTP 服务（CORS + Range）
  core/
    service.js       /getnote/* 全部路由（从 DSH 版原样搬来）
    vfs.js           文件系统适配层：绝对路径 → app.vault.adapter
    vault.js         笔记库算法（扫描、搜索、冲突、历史、标签……）
    settings.js      设置读写（存插件数据目录，不进库）
    net.js           用 node:http 实现的 fetch 兼容层（绕开渲染进程 CORS）
    openapi.js  biji.js  mcp-cloud.js  cloud-sync.js  sync.js
    archive.js  history.js  card.js
  view/
    panel.js         面板本体（从 DSH 版机械移植，React 写法，跑在 Preact 上）
    view.js          ItemView 外壳
  card/*.py          录音卡 Python 桥（蓝牙 / Wi-Fi）
  locale/*.json      界面文案
```

## 已知限制

- **仅桌面端**：录音卡要起 Python 子进程，移动端不可用。
- **录音卡导入依赖系统 Python**，且 `bleak` 版本需支持你的系统蓝牙栈。
- Wi-Fi 传输的 IP 探测依赖 `netsh`（Windows），其它平台回退到系统路由表。
- 云端接口是「得到大脑」的非公开 API，可能随对方调整而变化；凭证只存在本地。
